# 09 · 排序：LR、DeepFM与DIN

## 在同一个小池里比较排序模型

```text
同一召回小池 [A 装备清单, B 护肤, C 徒步路线]
      │ 组合请求前的特征、候选属性、候选来源
      ├─ LR：点击倾向与可解释的线性权重
      ├─ FM：用共享向量学习稀疏特征的二阶交互
      └─ DIN：用候选挑出最能解释这一条的历史
      ▼
三组输出的排序都和同条请求下的点击集合对比
```

**LR 基线的实验控制。** 先去掉任何可能泄漏点击的字段；训练集拟合 scaler 或类别词表，验证集选正则或特征；最后用一次测试集。对每条候选输出分数、队列 ID 和预测时点。用对照诊断选模型，不是模型越复杂越好。如果简单热度就很强，加入用户历史交叉项后只在一部分人改善，显示该分组而不是只强调总体。

## 手算 FM 二阶项

设点击样本只有三个激活特征，值都为 1，向量为 `a=(1,1), b=(2,0), c=(0,3)`。逐对点积是 2、3、0，总和为 5。快速写法先求和得到 (3,4)：平方和为 25；各 embedding 自身平方和为 2+4+9=15。差的一半也是 5。

这个等式说明了它怎么算得快；用低维 embedding 又让两对交叉能够共享学习到的分量。不过参数共享不意味着训练中没出现过的类别也能自动泛化，陌生 ID 仍需要 OOV 或内容特征。FM 不同于把类别 ID 当一个连续数字直接相乘。

## DIN 的历史掩码示意

| 用户历史位置 | 语义 | 候选：帐篷 | 候选：防晒 |
|---|---|---:|---:|
| 0 | 露营营地 | 0.8 | 0.2 |
| 1 | 美妆保养 | 0.1 | 0.7 |
| 2 | 跑鞋 | 0.2 | 0.1 |
| 3 | padding | 无效 | 无效 |

数值为示意，非模型实测。目标变化时每一列重新算权重，padding 必须永远不参与聚合。若空历史全被 mask，要定义稳定的零向量或默认表示，尤其不能对全 `-inf` 直接做 softmax。最小检查：两条 history 的真实序列一致、padding 长度不同，输出应一致；两条不同候选对应同一序列，兴趣表示可以不同。

## 从 LR 的手算开始

排序的输入是一条请求和一张候选。假设特征「历史主题重合」=1、「过去 7 天归一化热度」=0.4，系数分别 1.1 和 0.5，截距 -1.4。logit=$-1.4+1.1+0.2=-0.1$，点击概率约 0.475。真实点击时单样本交叉熵为 $-\ln(0.475)\approx0.744$，未点击时为 $-\ln(1-0.475)\approx0.644$。工程训练应该用 logits 版本的二元交叉熵，避免手工计算 $\ln(0)$。

AUC 可以理解为随机取一个正、一个负，模型把前者排更高的概率，同分计半。若对所有 logit 加 2，全局 AUC 不变，约 0.475 的样本却变为约 0.87，校准和 logloss 可能明显变差。想把 CTR 和其他概率做收益组合，必须先核对校准，不能只看 AUC。

## DeepFM：稀疏交叉与深层分支

LR 需要手工造「用户主题=徒步 × 候选主题=徒步」的交叉。FM 用 embedding 内积近似每对特征的权重，DeepFM 共享 embedding，一支计算二阶加和，另一支通过 MLP 学非线性交互。对三个 活跃特征，互动逐对为 $\langle e_1,e_2\rangle+\langle e_1,e_3\rangle+\langle e_2,e_3\rangle$。按 embedding 维度展开平方，可写成：

$$
\tfrac12\sum_d[(\sum_i e_{id}x_i)^2-\sum_i(e_{id}x_i)^2].
$$

因此计算可从二次枚举变成按特征数与维度线性累加。读 [DeepFM 论文](https://arxiv.org/abs/1703.04247) 时，重点辨别一阶项、明确的二阶项和 MLP 三路如何产生一个最终 logit。

## DIN：同一历史在不同候选下权重不同

用户历史是「露营」「护肤」「跑步」，当候选是帐篷，期望露营历史更重要；候选变成防晒，护肤历史的权重可更高。DIN 的局部激活用目标候选与各历史项构造交叉打分，再聚合历史，不强制把所有权重做 softmax 归一化。对 padding 位置必须 mask；否则变长 batch 的空值也会变成偏置。该表示随候选而变，适合对已召回的小池做排序；参考 [DIN 论文](https://arxiv.org/abs/1706.06978)。

实验先固定候选、特征快照和样本，再比较热门、训练的 LR、加入二阶项、加入目标注意力。保存逐请求 NDCG 与全局 logloss，记录冷用户和高历史长度组。当前仓库的 ItemCF 仅基于共现排序，并没有做 LR/DeepFM/DIN 训练；上述方案是实施章节，不能把阅读模型当作复现完成。

先把问题定义成在已曝光候选上预测click。只有曝光标签才有点击率意义；从全库随机采样的未观测物品不等同于曝光未点击。以人工采样集训练的概率也不自动等于真实CTR。

LR便于检查特征方向和泄漏；DeepFM结合FM二阶交互和DNN高阶非线性；DIN根据当前候选对历史行为加权，得到候选相关的兴趣表示。DIN通常更适合排序，因为不同候选需要不同的历史聚合。

## 特征分组

- 用户：训练期活跃度、历史偏好；冷用户有默认值。
- 物品：类目、内容向量、请求时可用的统计。
- 交叉：用户类目偏好与候选类目、历史与候选相似度。
- 上下文：时间和设备等可用字段，避免添加数据中不存在的信息。

先用LogLoss与AUC检查二分类，再用按请求NDCG看列表质量。最终训练样本应尽量贴近召回候选分布，否则模型在随机负例上很好、真实召回候选上很差。

进阶任务：选择DeepFM或DIN一个模型，保持训练/验证/测试和特征一致对比LR。不要把示例推荐器中的共现分数写成“DeepFM精排”。当前脚本没有训练CTR模型。

验收：解释padding和mask、类别OOV桶、训练期归一化参数、概率校准与负采样后验修正的区别。
