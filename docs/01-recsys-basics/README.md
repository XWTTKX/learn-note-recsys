# 01 · 推荐基础与笔记信息流目标

## 一屏推荐里，三个环节回答三个问题

```text
请求：用户打开首页，上次看过露营装备
          │
          ├─ 热门：当前大家在看什么
          ├─ ItemCF：看过这些内容的人还看过什么
          └─ 内容：哪些新笔记和露营有关
          ▼
召回：先找出一小组值得比较的笔记
          ▼
排序：根据这个用户、这条笔记和当前场景打分
          ▼
重排：限制同作者、去重、补足有效候选
          ▼
曝光：此刻起才可能产生点击、收藏等反馈
```

用一个反例记住分工：排序模型可以给「雨天露营」0.9 分，但三路都没找到这条笔记时，用户仍看不见它。另一个反例：召回已经把这条放进池，最终十条却全是同作者装备开箱；这可能需要列表约束、去重或排序重校准。先查到了哪一层，再选优化方法。

| 想达到的目标 | 直接看什么 | 不能单独说明什么 |
|---|---|---|
| 把用户可能喜欢的内容找出来 | 候选覆盖、Recall@K | 首页第一条是否合适 |
| 将正确的候选放在前面 | NDCG、MRR | 模型概率是否校准 |
| 长期主页体验更好 | 在线长期指标与保护指标 | 离线日志不能给出因果结论 |

练习：把「推荐更准」拆成两条量化目标，例如「对测试期新笔记，候选 Recall@100 上升」与「给定相同候选，预测排名 NDCG@10 不退化」。你会得到两个独立的实验，而不是一张含义不清楚的总分。

## 曝光之前和曝光之后

用户打开首页时，系统只有请求时刻前的数据。召回决定「哪些笔记值得进入小池」，排序决定「这些笔记谁先展示」，重排避免同作者或同主题挤满一屏。点了哪条要等展示后才知道，它是标签。比如用户昨天看过露营装备，今天在旅行模式打开主页。热门召回能保底，ItemCF 可能找同类装备，内容召回能覆盖刚发布的露营攻略。若新笔记不在任何候选池，精排打分再准确也看不到它。

点击主要衡量当下兴趣；收藏与持续使用可能适合其他目标。不要将「这条笔记没有点击」简单解释为「用户不喜欢」。放在第 20 位时用户可能从没滑到那里，无曝光的笔记更没有负反馈。用这一点理解日志评测为什么不等同于真实首页。

搜索由query表达当下意图；推荐往往只有用户历史与上下文，需要主动选择候选。相同用户在不同时间可能想看不同内容，不能只把用户ID当固定兴趣。

笔记推荐的教学目标是：从内容池产生候选，预测用户偏好，再兼顾多样性和新内容。我们使用公开Qilin笔记场景建立项目，不声称复原小红书线上生产系统。

## 业务目标与可观测标签

曝光是产生点击机会的前提，点击、阅读、收藏和点赞不是同一个目标。只追点击可能偏向标题党；只追停留可能偏向长内容。是否可做多任务，取决于数据是否有可靠标签、缺失语义和时间窗口。

离线日志记录的是历史策略挑选过的内容，未出现的内容是“未观测”，不能直接认为用户不喜欢。当前基线学习点击共现，不是经过校准的点击率模型。

验收：画出一次推荐请求的输入（历史、候选、上下文）与输出（有序笔记列表）；解释为什么推荐的历史不能含本次请求的点击结果。
