# 07 · 热门、ItemCF与多路召回

## 先把用户图转成笔记图

```text
训练用户点过：       每对获得一次贡献：      聚合后可作为索引：
u1 : A ─ B          AB += 0.5000           A ↔ B  约 0.3800
u2 : A ─ B ─ C      AB,AC,BC += 0.4307     B ↔ C  约 0.3800
u3 : B ─ C          BC += 0.5000           A ↔ C  约 0.2153
                    然后除 sqrt(受众A × 受众B)
```

注意图里为了展示只写无向对。代码对 a→b 和 b→a 分别记录，所以查任意种子时都可以取邻居。训练共现读的是「训练曝光内点击」，在线历史是请求传入的最近记录。没有训练边的种子可代表真实的兴趣，但该基线无法利用；将用户历史长度与可用种子数一起统计，就知道如何分组。

## 从邻居合并到最终返回

假设历史 `[A,C]`，候选 B 既是 A 的邻居也是 C 的邻居。其总协同分约 0.7600。A、C 作为已看项先排除。若候选池还有 D、E，且都没有图上的关联，D 的热门点数 7、E 的是 2，则顺序 B、D、E。若完全无历史，退化成按热门和 ID 排。不是把任何无分条目都删掉：在小目录仍可补全到 K。

写邻接版时考虑两个边界：列表截断提前去掉所有有贡献的候选时是否回退；多个种子同时给同一候选加分时，是否正确累加且只返回一次。用小例子对齐全目录版本，再上大样例压耗时。

| 实验设置 | 候选数 | 应同时看哪些量 |
|---|---|---|
| 热门与 ItemCF | 相等的最终 K | 分历史长短的 Recall 和 NDCG |
| 图邻接截到 20 与 100 | 固定 K | 生成时间、候选覆盖、排行稳定性 |
| ItemCF 加内容召回 | 相等的候选总预算 | 新笔记独有命中、老笔记退化、候选重合 |
| 去重或过滤历史 | 规则一致 | 去除数量、结果短列表率 |

<details>
<summary>追问：为什么“被同一批人看过”不等于内容语义相近？</summary>

用户可能因为同一专题运营、一个时期的曝光位置、或本身兴趣宽而同时点击两个不相干主题。ItemCF 表达的是行为关系，若业务希望覆盖刚发布且无反馈的主题，需加入内容信号。用曝光或时间窗口的细分诊断来解释原因。
</details>

## 从同点事件重建 ItemCF

用三位用户，点击集合分别为 U1={A,B}、U2={A,B,C}、U3={B,C}。本仓库对同一个用户的每个有序笔记对加 $w(u)=1/\log_2(2+|I_u|)$，再用物品受众人数归一化：

$$
s(A,B)=\frac{\sum_{u:A,B\in I_u}w(u)}{\sqrt{|U_A|\cdot|U_B|}}.
$$

这里 U1、U3 的权重各 0.5，U2 约 0.4307。A、B、C 的受众人数是 2、3、2。故 A–B 和 B–C 各约 0.3800，A–C 为 0.2153。对只有 A 历史的用户，B 的协同分约 0.3800、C 为 0.2153，返回 B、C。对只有 B 历史的用户，A 和 C 分一样，再按训练点击热度和 ID 决定。历史先去重，同一用户点击 A 两次，不会在当前排序里给 A 两倍权重。

分母防止高曝光笔记通过大共现次数无条件占优；活跃度权重缩小重度用户的单次贡献。它无法消除一条笔记在首页被优先曝光所造成的共现偏差，也不能为从未被点击过的笔记自动赋予相似度。常用改进包括行为时间衰减、对低共现对做平滑，以及围绕候选内容引入新笔记路径。每次只改一项，和同时间窗口的热门基线对照。

## 从教学代码到多路候选

当前基线对训练目录逐条计算相似分并排序，这对照逻辑清楚，规模大时慢。若请求历史有 H 个种子，目录有 N 个物品，当前打分约 $O(NH)$，排序另有 $O(N\log N)$。可将每个种子的邻接表按分数截断到 L 项，然后合并累加非零候选，将候选构建压至约 $O(HL)$，再加热门回退。注意仅取每个种子的 TopL 可能丢掉「每个列表都排第 L+1、加起来很强」的候选。先比较同 K 的排序一致率和正例召回，再选 L。

| 召回路 | 最适合 | 评估谁提供了新增正例 |
|---|---|---|
| 热门或近期热门 | 空历史、服务降级 | 冷启动请求独有命中 |
| ItemCF | 历史足够且目录稳定 | 用户级共现的增量 |
| 内容近邻 | 新笔记、长尾主题 | 按发布日期切片 |
| 双塔 | 可学习且低延迟的个性化 | 同候选预算相对基线的提升 |

练习：如果一个用户点击列表特别长，为什么构图会变慢？两两枚举为 $O(|I_u|^2)$，权重虽小仍要枚举。可取最近 N 项或按会话组织。这个改动也改变了图表达的含义，说明覆盖、时间窗口和指标变化，不能只报加速。

热门基线按训练点击计数排序，容易偏向头部但能作为冷启动兜底。ItemCF通过“同一用户喜欢过哪些内容”的共现估计相似度，再把用户历史物品的邻居合并。当前代码先按用户去重点击，对高活跃用户共现降权，再按物品用户数归一化。

这种ItemCF可以表示协同行为，却看不懂文本语义；新笔记没有交互时无法产生可靠邻居。图文内容召回能够补冷启动，但也可能只找到同主题而不符合用户偏好。

## 多路召回建议

| 通道 | 解决问题 | 必须记录 |
|---|---|---|
| 热门 | 新用户与兜底 | 时间窗口、头部覆盖 |
| ItemCF/Swing | 行为协同 | 共现统计截止时间 |
| 双塔 | 个性化向量匹配 | 模型与索引版本 |
| 内容相似 | 新笔记与长尾 | 内容模型、缺失比例 |

融合先用配额合并或轮转去重，保留通道来源。分数分布不同不能直接相加。联合Recall可能提升，但某通道的边际贡献需要“去掉此通道后下降多少”来观察。

验收：固定总候选数，对比热门、ItemCF、两路融合；报告候选去重率、每路独有命中和长尾覆盖。训练全量点击共现计算为O(Σ用户历史长度²)，本地demo面向学习；大规模要截断历史、稀疏计算与邻居Top K。
