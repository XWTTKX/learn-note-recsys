# 13 · 三阶段实战与实验矩阵

## 给实验做一个不乱串的路线图

```text
固定数据与时点 ──► 计数与覆盖审计 ──► 热门基线
                                     │
                                     ▼
                             加入 ItemCF 做对照
                                     │
                                     ▼
                           按请求回放一个错误样本
                                     │
                                     ▼
                           只在诊断支持处加召回/排序
```

在终端运行 `python3 scripts/coverage_lab.py --k 1` 和 `python3 scripts/coverage_lab.py --k 5`。先用自带数据验证脚本。把输出整理为两行表格，检查 OOV 率不随 K 变，宏上限可能上升，种子覆盖不变。若你改候选目录，OOV 率和上限才可能一起变；这给实验报告提供两个可独立控制的变量。

### 错误案例复盘模板

1. **请求：** 时间、历史长度、K、候选协议。
2. **目标：** 正例 ID、是否已看、是否在可用目录。
3. **轨迹：** 该候选来自哪一路、协同/热门排序、具体被哪一层截掉。
4. **改动：** 只换一个变量，并断言其他输入、切分与对照相同。
5. **核验：** 对比同一请求与整体/切片结果，补上新增成本或退化。

例：某条测试笔记当天才出现、目录不含它，去调 ItemCF 相似度毫无作用。用「增加请求时已发布的内容候选」作为假设；然后检查是否因此降低原来热门结果，报告 K 固定下的整体指标。真实 Qilin 的本地 toy 仅用于审计和练习，不能靠截取几个成功请求写业务提升。

## 实验一：先算理论覆盖，再看模型分数

```bash
python3 scripts/coverage_lab.py
python3 scripts/coverage_lab.py --data data/processed/qilin-toy.jsonl --k 5
```

第二条依赖已按第 06 章转换的本地文件。对合成数据，目录上限为 1；对已验证的 Qilin toy 时间切分，宏上限约 0.2911、微上限约 0.3101，有共现邻接种子的有效请求约 82.54%。这些数字和 ItemCF 的实际 Recall 不是一回事：它们分别描述「候选池容许的最好结果」和「有可用历史线索」。把 K 改成 1 再跑覆盖脚本，宏上限不能比 @5 更高，因为每条请求中的命中上限都不增。

## 实验二：找一个失败请求做对照

先从小子集取一条测试请求，打印历史、真实点击集合、过滤后的全目录、给定候选、两个协议下的排序。按顺序判断：(1) 点击是否在目录，(2) 是否被历史过滤，(3) 有没有 ItemCF 邻接，(4) 是否在 TopK。一次只动一个因素。把案例和相同协议的前后结果放在一起，若目录 OOV 整体高，则先改目录来源；若覆盖够但协同弱，可尝试截断历史、时间权重或内容召回，再比较同一切分。

## 实验三：有余力再加排序

固定同一个候选池，训练小的 LR 预测日志点击，对比共现排序和 LR，按请求计算 NDCG，另外用 logloss 检查概率，记录没有双类标签时 AUC 如何定义。禁止把给定候选评测的数字写成端到端召回成绩。LR 和更复杂的深度模型是学习任务，尚未提交训练实现。

## A：一周建立可信基线

跑合成请求，导入Qilin样例，检查ID与时间字段；用热门和ItemCF比较两种候选协议。产出字段字典、划分说明、数据统计、10个失败案例。toy实验只用于学习，不作为官方benchmark。

## B：两周完成一个模型改进

保留官方划分，选择ID双塔或内容双塔完成训练；验证候选召回；选择LR→DeepFM或LR→DIN的一条排序路线。先用小样本打通，再扩大规模。每次只改一个因素。

## C：一到两周深入一个问题

三选一：困难负采样与分布偏差、内容冷启动、离在线特征一致性。对搜广推面试，能够准确解释一个失败实验往往比堆叠更多模型更有价值。

| 实验 | 固定项 | 改动 | 观察指标 |
|---|---|---|---|
| R0→R1 | 数据、候选池 | 热门→ItemCF | Recall/NDCG/覆盖 |
| R1→R2 | 划分、Top K | 加双塔通道 | 边际Recall、延迟 |
| S0→S1 | 固定召回候选 | LR→DeepFM | AUC/LogLoss/请求NDCG |
| D0→D1 | 同排序分数 | 多样性重排 | NDCG与作者覆盖权衡 |

复制[实验模板](../../experiments/TEMPLATE.md)，先写假设再跑。与搜索项目合计建议六周：基础与数据两周，核心模型两周，工程与面试两周。资源估计在抽样实测后决定，完整百万内容训练不默认适合笔记本。
